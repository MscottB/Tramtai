Pruebas del 2026-11-12 con los programas reales, para fijar las recetas de la Tarea 2 (spec › «Comprobación con los
programas reales (M0)»). Siempre con carpetas de usuario y de configuración temporales: las instalaciones y sesiones
reales del usuario no se tocaron (huellas SHA-256 iguales antes y después, PATH de usuario del registro sin cambios).

- **Windows 11** (este equipo): instaladores de Claude Code y Antigravity con `USERPROFILE`, `HOME`, `APPDATA`,
  `LOCALAPPDATA` y `TEMP` en `bin/m0-v060/`; Codex y Copilot por su descarga oficial verificada (sus instaladores
  cambian el PATH de usuario del registro, que no se puede aislar: se probaron en el CI).
- **Windows Server 2025, Ubuntu y macOS** (runners de GitHub), con `scripts/agentes/probar-instalacion.{ps1,sh}` desde
  el workflow `agentes-compatibilidad.yml`: instalar una versión anterior, actualizar, inicio de sesión hasta el enlace y
  el código (cerrado a los 25 s) y desinstalar. En Windows Server, además, con la cuenta virtual de un servicio de
  prueba (`pruebas/m0agentes`). Ejecuciones:
  [43321116909](https://github.com/MscottB/Tramtai/actions/runs/43321116909) y
  [43322868158](https://github.com/MscottB/Tramtai/actions/runs/43322868158).
- **Ningún inicio de sesión se completó** (sin cuentas): se lanzó cada uno, se guardó lo que imprime y se cerró. Lo que
  pasa al aprobarlo sale del código de cada CLI, no de una prueba; la Tarea 4 lo confirma con el usuario.

Versiones: Claude Code 2.1.311 → 2.1.323, Codex 0.167.1 → 0.167.2, Copilot 1.0.108 → 1.0.109, Antigravity 1.5.7.

- **Se actualiza solo** en segundo plano (instalación nativa); se apaga con `DISABLE_AUTOUPDATER=1`.
- **Registro de Windows:** al arrancar registra `claude-cli://` en `HKCU\Software\Classes` (en Linux un `.desktop`, en

- **Cuenta virtual de un servicio:** se instala y lanza su inicio de sesión igual, en `C:\Windows\ServiceProfiles\<servicio>`.

### Inicio de sesión: `claude auth login`

Con tuberías basta (sin pty), en los tres sistemas y en la cuenta del servicio. Salida (stdout):

```
Opening browser to sign in…
If the browser didn't open, visit: https://claude.com/cai/oauth/authorize?code=true&client_id=…&redirect_uri=https%3A%2F%2Fplatform.claude.com%2Foauth%2Fcode%2Fcallback&…&state=…
Paste code here if prompted > 
```

- **Enlace:** en la línea `If the browser didn't open, visit: <url>`. Es el enlace «manual»: al aprobarlo, la página de
  `platform.claude.com` enseña un código para pegar. A la vez escucha en `localhost` (vale si el navegador está en el
  mismo equipo).
- **Pegar:** la última línea, `Paste code here if prompted > `, queda sin salto de línea. Lee líneas de la entrada
  estándar con la forma `código#estado`. Sin `#` escribe en stderr «Invalid code. Please make sure the full code was
  copied.» y sigue esperando; un código que el servidor rechaza termina con 1 y «Login failed: That code wasn't
  accepted…». Con la entrada cerrada sigue esperando (al `localhost`).
- **Navegador:** usa `BROWSER` o el ajuste `browser`; si no, `rundll32 url,OpenURL` (Windows), `open` o `xdg-open`. Con
  `BROWSER` apuntando a un programa que no existe no abre nada y no cambia la salida.
- **Final:** con éxito escribe «Login successful.» y sale con 0 (del código; no probado con una cuenta).
- **Con pty** (Linux, `script`): el enlace va dentro de un OSC 8 y con color, y las líneas acaban en CRLF.
- Salidas: `internal/agentes/claude/testdata/sesion-windows.txt`, `sesion-windows-codigo-rechazado.txt`,
  `sesion-linux-pty.txt`.

### Inicio de sesión: `codex login --device-auth`

Con tuberías basta. No abre el navegador. Salida (stdout):

```

Welcome to Codex [v0.167.2]
OpenAI's command-line coding agent

Follow these steps to sign in with ChatGPT using device code authorization:

1. Open this link in your browser and sign in to your account
   https://auth.openai.com/codex/device

2. Enter this one-time code (expires in 15 minutes)
   ABCD-12345

Continue only if you started this login in Codex. If a website or another person gave you this code, cancel.
```

- **Enlace:** la línea con `https://auth.openai.com/codex/device`. **Código:** la línea siguiente a «Enter this one-time
  code», 4 + 5 caracteres en mayúsculas y cifras (`EUAF-4QDG0` en la prueba). Caduca a los 15 min. No pide pegar nada.
- **Color:** con tuberías en Windows 11 y en Linux lleva ANSI (`ESC[94m…ESC[0m` en el enlace y el código); en Windows
  Server del CI y en la cuenta del servicio, no. Con pty, además, CRLF.
- **Requisito de la cuenta:** ChatGPT exige activar el inicio por código de dispositivo en sus ajustes de seguridad
  (docs de OpenAI, citado en `docs/equipo/m0-agentes.md`); no es un ajuste del CLI. La tarjeta lo tiene que decir.
- **Final:** no observado (sin cuenta). `codex login status` dice «Not logged in» y sale con 1 antes.
- Salidas: `internal/agentes/codex/testdata/sesion-windows.txt` (con color), `sesion-sin-color.txt`, `sesion-linux-pty.txt`.

### Inicio de sesión: `copilot login --device-code`

**La ficha usa `copilot login`, y eso no sirve:** en un escritorio local hace el flujo web (abre el navegador y espera en
`localhost`); solo usa el código de dispositivo en remoto, CI o Linux sin pantalla. Con `--device-code`, en todos.

Con tuberías basta. Salida (stdout):

```
To authenticate, visit https://github.com/login/device and enter code 1A2B-3C4D
Waiting for authorization...
```

- **Enlace y código** en la misma línea; código de 4 + 4 caracteres en mayúsculas y cifras. No pide pegar nada.
- **Además copia el código al portapapeles y abre el navegador** en la página del código, aunque sea con
  `--device-code`. Usa `BROWSER` y, si falla, el navegador del sistema; solo `COPILOT_DEBUG_BROWSER` (JSON con la orden)
  lo sustituye del todo. Si no puede, añade «Failed to open browser…» o «Failed to copy to clipboard… enter the code
  XXXX-XXXX manually.» (Linux sin pantalla). Con pty copia el código con OSC 52 (en base64).
- **Final:** no observado. Con éxito guarda el token en el almacén del sistema (en la cuenta virtual, el Administrador de
  credenciales funciona sin sesión: v0.58, anexo A).
- Muchas peticiones seguidas desde la misma IP dan «Login failed: Error: Failed to request device code: Bad Request»
  (visto una vez en macOS): el lector lo trata como error.
- Salidas: `internal/agentes/copilot/testdata/sesion-windows.txt`, `sesion-linux.txt`, `sesion-linux-sin-navegador.txt`,
  `sesion-linux-pty.txt`.

## Ajustes imprescindibles y requisitos

- **Ningún ajuste imprescindible** en la configuración de los CLI: los cuatro se instalan e imprimen su enlace y su código
  sin tocarla. Lo que aparece y no es imprescindible (spec › Fuera de alcance): la autoactualización de Claude, Copilot y
  Antigravity, y el registro de `claude-cli://` de Claude.
- **Ningún CLI necesita Node:** los cuatro tienen instalador o descarga oficial sin él. «Requisitos» (Tarea 6) no se
  construye. Lo único parecido: winget para el MSI de Copilot en Windows, que la descarga directa evita.
- **Ningún inicio de sesión necesita pty:** los tres funcionan con tuberías en los tres sistemas; con pty solo se añaden
  color, OSC 8/52 y CRLF. No se añade ninguna dependencia. (Con pty solo se probó en Linux: el `script` de macOS pide
  una terminal de verdad en su entrada, «tcgetattr/ioctl: Operation not supported on socket».)

## Decisiones para la Tarea 2

- **Órdenes:** las de las tablas. Copilot en Windows: descarga directa verificada (`Receta.Descarga`, con `URLSumas`) en
  `%LOCALAPPDATA%\GitHubCopilotCLI` (donde lo deja su MSI, así `copilot update` y una instalación con winget conviven), en
  vez de winget: no necesita winget ni administrador y sirve también para la cuenta del servicio. Requisito `""` en
  todas.
- **Inicio de sesión:** Claude `auth login` (`PidePegar`, el enlace en «If the browser didn't open, visit:»); Codex
  `login --device-auth`; Copilot `login --device-code` (cambia el `["login"]` de hoy). `PTY: false` en los tres.
- **Entorno al lanzar:** `CODEX_NON_INTERACTIVE=1` en los instaladores de Codex y sin `CODEX_RELEASE` al actualizar; la
  entrada estándar cerrada en los instaladores (solo Copilot `install.sh` mira `/dev/tty`, y sin terminal sigue).
- **Fijar versión:** Claude (argumento), Codex (`CODEX_RELEASE`), Copilot (`VERSION` o la URL); Antigravity no.
- **Encontrarlo después:** Claude no toca el PATH, así que la ruta de la receta (`~/.local/bin`) es la que vale; los
  demás cambian el PATH de usuario (Windows) o los archivos de arranque (Unix), que el servicio en marcha no ve: también
  por la ruta de la receta (Revisión 1).
- **Desinstalar:** ninguno tiene orden propia salvo winget; se borra lo de las tablas. Las líneas del PATH que dejaron
  sus instaladores se quedan (no son de Tramtai).
- **Versiones comprobadas en el M0:** Claude Code 2.1.311 y 2.1.323, Codex 0.167.1 y 0.167.2, Copilot 1.0.108 y
  1.0.109, Antigravity 1.5.7.

## Decisiones abiertas para el usuario

1. **Copilot en Windows:** ¿descarga directa verificada (propuesta) o winget, la orden que GitHub pone primero? La
   descarga es «Direct download» en la documentación de GitHub, pero Tramtai elige la carpeta.
2. **Autoactualización:** Claude, Copilot y Antigravity se actualizan solos y pueden pasar a una versión aún no
   comprobada; el uso normal no se bloquea, solo la preparación automática (spec). ¿Se deja así (propuesta) o se apaga
   con su variable al lanzarlos desde Tramtai?
3. **Codex por código de dispositivo** exige que el usuario lo active en ChatGPT › Seguridad. ¿Se avisa en la tarjeta
   (propuesta) o se ofrece también `codex login` (navegador y `localhost`) en el escritorio?
4. **Windows Server:** instalar e imprimir enlace y código funciona con la cuenta virtual; falta comprobar que la sesión
   queda guardada al aprobarla, con las cuentas del usuario (propuesta: en la prueba final).
