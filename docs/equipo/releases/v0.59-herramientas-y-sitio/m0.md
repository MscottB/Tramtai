# Evidencia M0: Claude Code, Codex y opencode contra Tramtai

Pruebas con los programas reales el 2026-10-31 en Windows 11, con la suscripción del usuario y `claude/haiku`. Sirven a
la spec de la v0.59 (sección «Herramientas») y fijan los valores que escribirán las Tareas 3 a 5.

## Cómo se hizo

- **Copia de prueba:** `bin/m0-herramientas/` (portable, puerto 17388), compilada de esta rama. Nunca el Tramtai
  instalado ni su puerto 17373.
- **Datos:** `terminos aceptar` y una API de prueba, `tramtai acceso crear m0b --grupo Herramientas`. La clave no se
  guarda en ningún archivo del repositorio.
- **Aislamiento:** cada programa con su carpeta de configuración temporal (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`,
  `XDG_CONFIG_HOME` y las demás XDG) y sin las variables `ANTHROPIC_*`, `CLAUDE_*` ni `CODEX_*` de la sesión. Nunca se
  tocó el `~/.claude`, el `~/.codex` ni el `~/.config/opencode` del usuario.
- **Qué llegó a Tramtai:** un proxy de registro entre el programa y la copia (ruta, cabeceras, campos del cuerpo) y el
  Historial de la copia.

## Lo que cambia respecto a la spec

1. **La URL lleva el nombre de la API.** La clave de una API solo vale en `http://127.0.0.1:<puerto>/p/<api>/anthropic`
   y `http://127.0.0.1:<puerto>/p/<api>/openai/v1`. En `/anthropic` y `/openai/v1` (sin `/p/<api>`) solo vale la clave
   del espacio, y da 401 con la de una API.
2. **El nombre de la API no puede ser «Claude Code».** `contrato.NombrePuntoValido` pide `^[a-z0-9][a-z0-9_-]{0,39}$`.
   Las APIs de las herramientas se llaman `claude-code` y `codex` (el id de la herramienta); «Claude Code» y «Codex» son
   el nombre que enseña la UI.
3. **`apiKeyHelper` lo ejecuta `cmd.exe` en Windows.** No existe `cat`. La orden va entre comillas:
   `"C:\Users\Ana María\…\tramtai.exe" herramientas clave claude-code`. Se probó una ruta con espacio y tilde.

## Claude Code 2.1.288

- **Archivo usado:** `$CLAUDE_CONFIG_DIR/settings.json`:

  ```json
  {
    "env": {
      "ANTHROPIC_BASE_URL": "http://127.0.0.1:17388/p/m0b/anthropic",
      "ANTHROPIC_MODEL": "claude/haiku"
    },
    "apiKeyHelper": "\"C:\\ruta con espacios\\clave.cmd\""
  }
  ```

- **Orden:** `claude -p "di hola"`. Responde (exit 0).
- **Qué llega:**
  - `POST /p/m0b/anthropic/v1/messages?beta=true`, con streaming;
  - la cabecera `anthropic-beta` (lista de betas, p. ej. `context-management-2025-06-27`) y `anthropic-version`;
  - la clave de `apiKeyHelper` en `Authorization: Bearer` y en `x-api-key` a la vez;
  - `model` entero: `claude/haiku`;
  - `HEAD /…/anthropic/api/hello`, una comprobación que da 401 sin consecuencias.
- **Campos del cuerpo:** `model`, `messages`, `system`, `tools` (unos 78 000 caracteres), `metadata`, `max_tokens`,
  `thinking` (`{"type":"adaptive","display":"omitted"}`), `context_management`, `safeguards`, `output_config` y `stream`.
- **Lo que fallaba:** `400 parámetro desconocido: context_management`. Tras él, `safeguards` y `output_config`
  eran igual de desconocidos, y `thinking` figuraba como no soportado aunque venga en `adaptive` (por el código; el 400
  se detenía en el primero). **Arreglado** (ver abajo).
- **Avisos del programa (stderr, no impiden nada):**
  - «`claude/haiku` isn't described by this version's model catalog»: Claude Code no conoce el modelo y supone una
    ventana de 200 000 tokens;
  - un aviso de facturación del modo automático porque la puerta de enlace no lo implementa.
- **Variable de entorno que manda:** si el programa se lanza con `ANTHROPIC_BASE_URL` ya puesta (la app de escritorio o
  un ejecutor), Claude Code ignora la de `settings.json` («Ignoring ANTHROPIC_BASE_URL from userSettings»). La Ayuda
  debe avisarlo.

## Codex 0.160.0

- **Archivo usado:** `$CODEX_HOME/config.toml`:

  ```toml
  model = "claude/haiku"
  model_provider = "tramtai"

  [model_providers.tramtai]
  name = "Tramtai"
  base_url = "http://127.0.0.1:17388/p/m0b/openai/v1"
  wire_api = "responses"

  [model_providers.tramtai.auth]
  command = "C:\\ruta con espacios\\Ana María\\clave.cmd"
  ```

- **Orden:** `codex exec --skip-git-repo-check "di hola"`. Responde (exit 0), con streaming.
- **Qué llega:**
  - `POST /p/m0b/openai/v1/responses`, `stream: true`;
  - `model` entero: `claude/haiku`;
  - `Authorization: Bearer` con la salida de `auth.command`; la ruta con espacio y tilde funciona;
  - `GET /p/m0b/openai/v1/models?client_version=0.160.0` (tres veces al arrancar).
- **Campos del cuerpo:** `model`, `instructions`, `input`, `tools`, `tool_choice`, `parallel_tool_calls`, `reasoning`,
  `store`, `stream`, `include`, `prompt_cache_key` y `client_metadata`.
- **Herramientas que envía:** funciones (`exec_command`, `write_stdin`…), un `namespace` (`multi_agent_v1`, con funciones
  dentro) y `web_search`.
- **Lo que fallaba:** `400 parámetro desconocido: client_metadata` y, después, `herramienta de tipo namespace no
  soportada`. **Arreglado** (ver abajo).
- **Límite que queda:** Codex pide `GET …/models` y espera su propio formato (`models`), no el de OpenAI (`data`). Falla
  al decodificarlo, escribe dos líneas `ERROR codex_models_manager` en stderr y avisa de que no tiene metadatos del
  modelo (`Model metadata for claude/haiku not found`). Funciona igual con los metadatos por defecto. No se arregla en
  esta versión; la Ayuda lo explica.

## opencode 1.19.3

- **Archivo usado:** `$XDG_CONFIG_HOME/opencode/opencode.json` (en Windows, sin `XDG_CONFIG_HOME`, es
  `~/.config/opencode/`):

  ```json
  {
    "$schema": "https://opencode.ai/config.json",
    "model": "tramtai/claude/haiku",
    "provider": {
      "tramtai": {
        "npm": "@ai-sdk/openai-compatible",
        "name": "Tramtai",
        "options": { "baseURL": "http://127.0.0.1:17388/p/m0b/openai/v1", "apiKey": "<clave>" },
        "models": { "claude/haiku": { "name": "claude/haiku" } }
      }
    }
  }
  ```

- **Orden:** `opencode run -m tramtai/claude/haiku "di hola"`.
- **Qué llega:** `POST /p/m0b/openai/v1/chat/completions` con streaming y `stream_options.include_usage`; `model`
  entero; la clave del archivo. No pide `/models`. La primera petición (título de la sesión) responde bien.
- **Lo que no funciona:** la petición principal falla con
  `error_agente: API Error: 400 You're out of extra usage` del propio CLI de Claude. La ruta de Tramtai no tiene culpa:
  - el mismo cuerpo sin herramientas falla igual;
  - recortando el mensaje de sistema de opencode (28 000 caracteres) responde con 6 000 y falla con 10 500;
  - una petición pequeña directa a `claude/haiku` responde bien en la misma cuenta.
  - No se aisló la causa (¿el mensaje de sistema de otro programa con la suscripción de Claude?). La Tarea 5 debe
    escribir el archivo y decir en la Ayuda que opencode con Claude por suscripción puede dar este error.
- **Descarga:** al primer uso opencode baja de npm `@ai-sdk/openai-compatible` a su carpeta de caché.

## Qué se arregló en las rutas de Tramtai

Cada arreglo tiene su prueba en `internal/api/api_test.go`, vista fallar antes de arreglar:

- **`TestAnthropicAceptaPeticionDeClaudeCode`:** `context_management`, `safeguards` y `output_config` se ignoran con
  aviso (`Tramtai-Advertencia`). `thinking` con `adaptive` o `disabled` se acepta; con `enabled` y presupuesto sigue
  dando 400.
- **`TestRespuestasAceptaPeticionDeCodex`:** `prompt_cache_key` y `client_metadata` se ignoran con aviso. En
  `/openai/v1/responses`, las herramientas que no son funciones (`namespace`, `web_search`) se dejan fuera con aviso
  (`tools[namespace]`) y las funciones se respetan. En chat y en Anthropic siguen dando error.

`docs/api.md` recoge los dos cambios.

## Para las Tareas 3 a 5

- La API de cada herramienta se llama `claude-code` o `codex`; las URLs llevan `/p/<api>`.
- Claude Code usa también `x-api-key`; Tramtai acepta las dos cabeceras.
- Una ruta con espacios o tildes en la orden funciona si va entre comillas (Claude Code) o entera en `command` (Codex).
- Claude Code muestra el aviso del modelo desconocido mientras el modelo sea `agente/modelo`.
